The Supabase Booking row and related customer/item rows are the source for mobile booking data. Live catalog verification confirms payment preference, pickup/return methods and addresses, appointment/notes, voucher/points, per-leg distances and per-leg delivery fees. Preserve compatibility with older rows whose newer return fields are null. Explicit web return edits mirror both pairs so a cleared address cannot reappear through fallback.

Display business data on Booking details and inspection: customer name/phone/email/avatar/profile address, receiving/return addresses and appointment, service/garment/unit/quantity/weight/notes, voucher/points, payment preference and pickup/return distance/fee. Avoid exposing account credentials or internal retry tokens. The database already contains the fields; no new columns or production row backfill is needed. The existing private.copy_booking_delivery_fee_to_order trigger must use inspected home/store methods and mobile aliases, because its unconditional sum would overwrite the Laravel total. Persist inspected methods inside the same transaction before order insertion; update only this function, preserving its signature, private security boundary and grants.

Do not call routing/geocoding or overwrite the stored mobile fee snapshot. Zero is a valid stored fee, not an instruction to reprice. Web form fee values are never trusted. Preview applies the selected methods to the same fee snapshot.
