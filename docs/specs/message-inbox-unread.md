# Order message inbox

Conversations with messages come first, sorted by their latest message timestamp; orders without messages follow in creation order. UTC message timestamps are never compared against local order timestamps. Stable order ID breaks ties. Message aggregates are grouped and joined once per list query, avoiding per-order scans. The paginated list refreshes every three seconds while visible and online, and immediately after the open conversation synchronizes through existing Supabase Realtime.

A red dot means an incoming customer-to-store message has status `Đã gửi` or `Đã nhận`. Reading is shared by the store, consistent with the existing mobile `mark_chat_thread_read` contract. A CSRF-protected, permission-checked POST takes the highest valid message ID loaded into the visible conversation as a read boundary. Incoming messages in that thread up to this boundary, including older history outside the latest 100-message window, become read. Unrelated threads, messages with higher IDs and outgoing messages are excluded. This is a shared thread-read boundary, not an exact transaction snapshot: PostgreSQL allocates IDs before commit, so an overlapping transaction committed later with a lower ID is included in the acknowledgement. GET requests never mutate read state. Hidden tabs pause synchronization and acknowledgements. Existing messages, pagination and message-send behavior remain intact.

Acceptance: an old order with a new customer message moves above newer orders; its dot persists while another conversation is open; opening it clears the dot after acknowledgement; reloading preserves read status; another incoming message restores the dot. Session expiry and permission loss must prevent both inbox access and read writes.
